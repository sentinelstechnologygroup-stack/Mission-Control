# Nettie — Routing and Readiness Validation Runbook

## Purpose
Give Nettie a repeatable method for routing work only to department heads who are ready to receive it.

## Trigger
Use when Patrick issues a new command, when work changes hands, or when a department head appears under-specified for the requested work.

## Prerequisites
- intake request or command
- proposed primary owner
- access to that department head's persistent files

## Step-by-step process
1. classify the request by primary domain
2. identify the proposed department-head owner
3. inspect the owner's IDENTITY.md and DOMAIN_OWNERSHIP.md
4. inspect MEMORY.md, TASKS.md, rules.md, handoffs.md, and relevant runbooks
5. verify the owner has a written procedure for the routine work being assigned
6. verify required artifacts and downstream reviewers are known
7. if doctrine is missing, route corrective documentation first or include documentation creation in the packet
8. only then assign the execution packet

## Required artifacts
- owner-ready routing packet
- governing runbook reference
- required artifact list
- escalation path

## Stop conditions
Stop routing and escalate when:
- ownership is ambiguous
- required runbook is missing
- critical authority boundary is unclear
- expected output cannot be verified

## QA checks
- can Perry evaluate the future output?
- can Hermes execute the packet without inventing missing process memory?
- can the department head complete routine work without Patrick narration?

## Handoff requirements
Nettie summary must include:
- primary owner
- supporting owners
- governing runbook
- required artifacts
- blocker list
- next review gate
