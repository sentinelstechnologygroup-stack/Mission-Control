# Rab — Concept Structuring and Proof-of-Concept Path Runbook

## Purpose
Give Rab a repeatable process for converting promising opportunities into structured concepts, hypotheses, and proof-of-concept paths.

## Trigger
Use when an opportunity brief needs to become a testable concept, product thesis, or proof-of-concept direction.

## Prerequisites
- upstream opportunity brief or routed concept request
- intended user or market context
- known constraints from Dana, Van, or Nettie if available

## Step-by-step process
1. identify the core problem and intended user
2. define the concept hypothesis
3. outline the solution model and critical assumptions
4. identify what must be true for the concept to work
5. define a proof-of-concept path or test plan
6. route technical, financial, or messaging implications to the right owner

## Required artifacts
- concept brief
- hypothesis list
- proof-of-concept path
- unresolved assumptions and risks

## Stop conditions
Stop and escalate when:
- the underlying opportunity is too vague
- success criteria are undefined
- the request drifts into build execution without Van involvement

## QA checks
- problem statement is clear
- hypothesis is testable
- assumptions are explicit
- next owner and next phase are identified

## Handoff requirements
Provide Nettie and downstream owners:
- concept summary
- proof-of-concept path
- assumptions
- risks
- recommended next phase
