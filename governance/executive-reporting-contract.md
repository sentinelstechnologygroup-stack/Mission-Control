# Executive Reporting Contract

Status
- Standing Mission Control doctrine
- Applies to project reporting, CI reporting, pressure-test reporting, resource requests, and executive handoffs
- Extended by /home/patrick/mission-control/governance/executive-ci-enforcement-framework.md
- Extended by /home/patrick/mission-control/governance/agents-ci-mandate.md

## Daily executive status minimum
Every executive daily status report should include:
- executive
- department
- active projects
- status by project
- blockers
- decisions needed
- risks
- next actions
- CI work completed that day

## Daily executive CI minimum
Every executive daily CI report must include:
- executive
- department
- date
- internal CI completed
- external learning completed
- trigger issue or opportunity
- observed issue
- implemented fix
- validation result
- doctrine candidate status: locked / pending validation / not promoted
- unresolved blocker, if any
- key lesson learned
- what changed in thinking or approach
- what was applied
- what worked
- what failed
- evidence / artifacts
- should become: memory / doctrine / checklist / template / workflow / none
- next CI step
- resource requests
- escalations needed
- CI RECORD(s) created
- CI LEARNING RECORD(s) created
- daily independent-learning completion status: completed / missed

## Weekly executive CI report minimum
Planning weeks run Sunday through Saturday.

Every executive weekly CI report must include:
- executive
- department
- week covered
- internal CI completed
- external learning completed
- key lesson learned
- what changed in thinking or approach
- what was applied
- what worked
- what failed
- what needs improvement
- next week's CI focus prioritized
- resource requests if any
- Patrick review or approval requests
- proposed doctrine / memory / checklist / template / workflow updates
- self-identified behavior concerns if any
- evidence bundle

## Saturday upcoming-week planning packet minimum
Every Saturday report from Nettie must also include the proposed CI workload for the upcoming Sunday-through-Saturday week. For each executive, include:
- planned internal CI focus
- planned external capability learning focus
- expected artifacts
- resource requests if any
- items needing Patrick review or approval
- carryover from the prior week if any

## Weekly Nettie executive-summary minimum
Nettie's weekly executive CI wrap-up must include:
- top 3 improvements across the company
- biggest failure or miss
- strongest growth signal
- weakest performance signal
- recommended focus areas for next week
- high performers
- underperformers
- stagnation-risk executives
- all active resource requests with status
- the proposed CI workload for the upcoming Sunday-through-Saturday planning week
- evidence coverage note: which executives had validated CI evidence, which had none, and what would count as valid evidence tomorrow

## Pressure-test report minimum
Every pressure-test assignment or completion record must include:
- executive
- department
- why the test was assigned
- objective
- type: execution / decision / integration / stress / learning application
- expected output
- required artifacts
- time constraint if applicable
- success criteria
- completion report:
  - what they did
  - how they approached it
  - what worked
  - what failed
  - what they would improve
  - what external learning was applied if any
  - artifact paths / evidence
  - final decision or recommendation
- status: assigned / in progress / completed / failed / stalled
- flags raised

## Resource request minimum
Every resource request must include:
- resource requested
- purpose
- expected impact
- application plan
- urgency level
- cost if applicable
- alternatives considered if applicable
- risk of not having it
- current status: approved / pending / rejected / deferred / needs more justification

## Evidence standard
Reports should cite file paths, run ids, session evidence, QA findings, metrics, or concrete examples when available.

## Honesty rule
Sparse output must be reported as sparse output. Missing work must not be disguised with filler language.

## Behavior-enforcement rule
When passive behavior, low-quality CI, fake learning, stagnation, over-internal focus, or over-external non-application are detected, the report must:
- flag the issue explicitly
- cite evidence
- recommend correction
